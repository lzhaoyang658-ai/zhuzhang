# 第 4 阶段技术开发文档｜Beta 家庭协作与权限

## 一、完成范围

- 项目所有者可邀请家庭协作者，V1 上限为每项目 5 位。
- 邀请角色支持共同管理者和只读成员，链接默认 7 天有效，数据库只保存令牌哈希。
- 邀请人可以撤销待接受邀请；接受后可以调整角色或移除成员。
- 共同管理者可查看并编辑业务数据、确认增减项，但不能管理成员。
- 只读成员可以查看完整项目，所有写接口返回 403。
- 非项目成员访问项目或下属对象时统一返回 404，避免泄露对象是否存在。
- 邀请、加入、改权、移除和撤销邀请全部进入项目审计时间线。

## 二、数据结构

- `User`：本地演示账号身份、姓名、邮箱与状态。
- `ProjectMembership`：用户和项目的唯一关系，角色为 `owner/co_manager/viewer`，支持撤销状态。
- `ProjectInvite`：项目、邮箱、目标角色、令牌哈希、邀请人、状态与有效期。

迁移 `c7e4f1209a31` 会为既有项目回填 `demo-owner` 所有者关系。新建项目时自动创建当前用户的所有者成员关系。

## 三、权限矩阵

| 能力 | 所有者 | 共同管理者 | 只读成员 |
|---|---:|---:|---:|
| 查看项目全部数据 | 是 | 是 | 是 |
| 编辑报价、预算、增减项、验收、付款、证据 | 是 | 是 | 否 |
| 确认增减项 | 是 | 是 | 否 |
| 邀请、改权、移除成员 | 是 | 否 | 否 |
| 导出完整项目包 | 是 | 否 | 否 |

外部确认链接继续是独立的最小权限入口，不加载项目会话，也不能访问项目首页。

## 四、接口

- `GET /api/v1/session`：当前本地身份及项目角色。
- `GET /api/v1/projects/{id}/members`：成员、当前角色和待处理邀请。
- `POST /api/v1/projects/{id}/invites`：创建邀请并仅在本次响应返回明文令牌。
- `GET /api/v1/invites/{token}`：读取邀请的最小必要信息。
- `POST /api/v1/invites/{token}/accept`：创建或关联用户并加入项目。
- `PATCH /api/v1/project-memberships/{id}`：所有者调整协作者角色。
- `DELETE /api/v1/project-memberships/{id}`：所有者移除协作者。
- `POST /api/v1/project-invites/{id}/revoke`：撤销待处理邀请。

除公开邀请和外部确认接口外，全部项目业务接口都已接入成员访问校验；写接口额外校验角色。

## 五、前端体验

成员面板采用 12 栏无空洞权限工作台，包含权限解释、成员目录、角色选择、邀请创建、待接受邀请和本地身份切换。邀请落地页只展示项目名称、被邀请邮箱、目标角色及该角色的权限说明。

只读身份在顶栏显示明确标记并禁用主写入入口。后端仍是最终权限边界，不能依赖前端按钮隐藏。

## 六、验证结果

- 后端 15 项测试通过，新增覆盖邀请接受、只读写入拒绝、跨项目 404、共同管理者提升和成员移除。
- 全新数据库可从初始版本连续升级到 `c7e4f1209a31`，三张权限表及演示所有者回填正确。
- TypeScript、ESLint 和 Next.js 生产构建通过。
- Playwright 验证所有者创建邀请、家人接受、只读身份进入项目、移动端成员面板、角色提升为共同管理者。
- 浏览器写请求返回 `POST 201`、`PATCH 200`，零控制台错误、零失败网络请求；390px 视口宽度为 `390/390`，无页面横向溢出。

## 七、安全边界与下一步

本阶段的 `X-Demo-User-Id` 仅用于本地演示和权限验收，不是生产认证。公网部署前必须完成邮箱或短信验证码登录、服务端安全会话、CSRF 防护、登录与邀请速率限制、近期登录校验和账号恢复；之后再进入项目购买权益与通知中心。
