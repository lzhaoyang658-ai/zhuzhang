# 阶段 9：正式报告与私有制品

## 阶段目标

把阶段 8 的项目摘要升级为可正式交接的多页报告，并为生产对象存储建立清晰边界。报告需要覆盖 PRD FR-5.3 的核心数据，保持中文字体、表格、图片和分页可读；导出文件需要在生成、存储和下载之间具备可验证的完整性。

## 已完成范围

- 正式 PDF 从单页摘要升级为多页流式报告，长表格可自动分页并重复表头。
- 增加封面、项目概况、数据范围、报告版本和重要使用边界。
- 增加预算资金上限、合同基线、预测结算、累计付款、风险预留与剩余资金摘要。
- 增加全部合同基线版本、确认人、确认时间和变更原因。
- 增加增减项日期、原因、类别、区域、确认状态和带符号金额。
- 增加付款节点、计划金额、有效实付、最新验收与未关闭问题。
- 增加验收明细、付款与冲正记录、原始报价目录和项目时间线。
- 图片类证据在报告中生成等比例缩略图，非图片证据保持目录记录。
- 每页统一页眉、页码，金额继续复用页面同一预算计算服务。
- ZIP 新增 `验收与付款.csv` 和 `附件目录.csv`。
- 新增私有制品存储抽象，本地实现只接受受控对象键并阻止目录越界。
- 任务记录新增 SHA-256、存储后端、报告版本与 PDF 页数。
- 文件进入私有目录前计算 SHA-256，下载前重新计算并校验；不一致时拒绝下载。
- 工作台展示报告页数、版本和 SHA-256 校验状态。

## PDF 结构

正式报告 `formal-v2` 默认包含以下章节：

1. 封面、项目概况、生成时间、数据范围与使用边界；
2. 预算与合同边界、合同基线版本；
3. 增减项及确认状态；
4. 付款节点、验收问题、验收明细、付款与冲正；
5. 附件缩略图、证据目录和原始报价目录；
6. 项目时间线与报告使用边界。

日期范围影响过程记录、验收付款和附件目录；封面预算摘要始终反映生成时的项目当前状态，并在报告末页明确说明这一口径。

## 私有制品边界

`LocalPrivateArtifactStorage` 提供以下最小能力：

- 将暂存文件写入受控对象键；
- 解析本地私有路径；
- 删除过期制品；
- 根据已记录 SHA-256 校验文件完整性。

对象键由服务端按 `项目 ID / 任务 ID.zip` 生成。存储层会对解析后路径执行根目录约束，客户端不能提交路径。配置 `ARTIFACT_STORAGE_BACKEND=local` 选择当前实现；后续接入对象存储时，导出器和业务接口无需再了解具体存储路径。

## 数据结构

迁移 `c72f61a04d8e_formal_export_report_metadata.py` 为 `project_export_jobs` 增加：

- `artifact_sha256`：ZIP 文件 SHA-256；
- `storage_backend`：制品存储实现；
- `report_version`：报告模板版本；
- `report_page_count`：正式 PDF 页数。

旧任务保留原有状态；新任务完成后写入全部元数据。失败或重新生成时会清空旧制品元数据，避免把旧校验结果误用于新文件。

## 前端

档案工作台继续遵守用户指定的 `gpt-taste` 设计规范。本阶段没有改变已验证的 Editorial Split、8+4 / 4+4+4 Bento、横向手风琴、滚动固定和卡片堆叠结构，只在正式报告内容和任务卡片中增加可信元数据。

成功任务会显示：

- 正式报告页数；
- `formal-v2` 模板版本；
- `SHA-256 已校验`；
- 文件体积与 24 小时有效期。

- TypeScript、ESLint 和 Next.js 生产构建通过。

- 下载包包含 PDF、四份 CSV 和导出清单；浏览器控制台与失败 API 请求均为 0。
- 1440px 和 390px 横向溢出均为 0，所有按钮都有可访问名称。

## 当前边界

- 当前私有制品后端是本地文件系统；生产对象存储适配器尚未绑定具体云厂商和凭据。
- 进程内线程池仍只适合单机 Beta；生产多实例需要独立队列、租约、超时、重试次数和死信告警。
- PDF 当前嵌入图片类证据缩略图；Word、Excel、PDF 等附件只进入目录和原始附件包，不做内容预览。
- 超大项目尚未拆分报告包与附件包，也未实现分卷下载。
- SHA-256 保证下载文件与生成时记录一致，不代替数字签名、可信时间戳或第三方存证。
