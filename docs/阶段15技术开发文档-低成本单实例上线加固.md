# 阶段 15 技术开发文档：低成本单实例上线加固

## 1. 阶段目标

在不购买 RDS、ECS 和独立 Worker 的前提下，把现有 veFaaS 单实例、SQLite、私有 TOS 和内嵌任务模式加固到可供个人及小范围 Beta 使用的状态。本阶段不把 SQLite 描述为多实例生产数据库；后端必须固定为最小 1、最大 1 个实例。

## 2. 当前部署边界

- 前端 `<frontend-app>` 按请求弹性启动。
- 后端 `<backend-app>` 固定 `1 ~ 1` 个实例，避免两份 SQLite 数据库同时接收写入。
- 报价解析和项目档案使用 `embedded` 模式，共享 API 进程资源。
- 原始文件、导出制品和 SQLite 恢复点写入北京地域私有 TOS。
- 该形态面向个人及小范围验收，不适合高并发、跨地域容灾或多实例扩容。

## 3. SQLite 恢复点

每次备份先使用 SQLite Online Backup API 生成一致性副本，再执行 `PRAGMA integrity_check`。通过后计算文件大小和 SHA-256，并依次写入：

1. `snapshots/<UTC 时间>-<校验和前缀>.sqlite3`：不可变恢复点；
2. `latest.sqlite3`：兼容阶段 13 的最新副本；
3. `latest.json`：记录恢复点对象键、生成时间、大小和完整 SHA-256。

清单最后写入，因此快照上传中断不会覆盖上一个可恢复版本。恢复时优先读取清单，下载对应不可变快照，并同时校验文件大小、SHA-256 和 SQLite 完整性；所有检查通过后才用原子替换写入运行路径。已有本地数据库若完整则不会被覆盖，若损坏则会尝试从云端恢复。

`DATABASE_BACKUP_RETENTION_COUNT` 控制不可变快照保留数量，默认 24。清理失败不会把一个已成功上传的恢复点标记为失败。

## 4. 备份健康

备份调度器启动后立即执行一次备份，之后按 `DATABASE_BACKUP_INTERVAL_SECONDS` 周期运行。`/health/ready` 增加脱敏的 `backup` 字段：

- `healthy`：最近一次备份未超过新鲜度阈值；
- `pending`：进程启动后尚未产生成功备份；
- `stale`：最近成功备份超过 `DATABASE_BACKUP_MAX_AGE_SECONDS`；
- `failed`：最近一次尝试失败且晚于最近一次成功；
- `disabled` / `not_applicable`：未启用或不是文件型 SQLite。

健康响应只展示校验和前 12 位、文件大小、时间和异常类型，不展示桶名、对象键、Endpoint 或凭据。默认备份异常将服务标为 `degraded`，但仍保持 HTTP 200，避免一次 TOS 抖动同时中断业务；设置 `DATABASE_BACKUP_REQUIRE_READY=true` 后才会返回 503。

## 5. 非破坏性恢复演练

部署环境可执行：

```bash
python verify_database_backup.py
```

该命令只把远端恢复点下载到临时文件，执行大小、SHA-256 和 SQLite 完整性校验，然后删除临时文件，不替换线上数据库。输出不包含密钥、桶名和对象键。

真正的空实例恢复仍由 `production_bootstrap.py` 在 Alembic 迁移前执行。若远端恢复失败且本地库仍可用，API 会继续启动并在平台日志中留下异常；若本地库不存在且没有可用恢复点，Alembic 会创建空库，这种情况必须通过备份健康和业务数据验收发现。

## 6. 内嵌任务重启恢复

报价和档案任务继续使用数据库状态、尝试次数与租约恢复。阶段 15 修复了一个重启边界：处于指数退避等待期的 `queued` 任务不再因 API 重启而清空 `next_attempt_at`，而是按剩余等待时间重新注册定时器，避免短时间内重复解析、重复导出或重复调用模型。

运行中的内嵌任务在进程退出后仍会重新排队；达到最大尝试次数的任务进入死信，并保留现有人工重试入口。

## 7. 配置

```dotenv
DATABASE_BACKUP_ENABLED=true
DATABASE_BACKUP_INTERVAL_SECONDS=300
DATABASE_BACKUP_MAX_AGE_SECONDS=900
DATABASE_BACKUP_RETENTION_COUNT=24
DATABASE_BACKUP_REQUIRE_READY=false
QUOTE_EXECUTION_MODE=embedded
EXPORT_EXECUTION_MODE=embedded
HEALTH_REQUIRE_WORKERS=false
```

后端 veFaaS 实例范围必须保持 `1 ~ 1`。升级到多实例前必须先切换 PostgreSQL 和独立 Worker。
