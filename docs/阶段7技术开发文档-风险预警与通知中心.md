# 阶段 7：风险预警与通知中心

## 阶段目标

将预算总账、增减项和付款节点中的风险从页面即时提示扩展为可持续跟踪的站内通知：每条风险能够定位到具体项目对象，同一对象同一状态不重复生成，条件消失后自动关闭并保留记录。同时提供已读状态、跨项目筛选、邮件摘要偏好与可由生产调度器执行的邮件摘要任务。

## 已完成范围

- 完整实现 PRD 的 A1–A8 风险规则。
- 风险按用户和项目成员独立投递，项目之间、账号之间相互隔离。
- 同一用户、项目、规则和业务对象使用唯一去重键，不重复创建通知。
- 风险解除时自动转为“已解除”，记录不删除；相同风险再次出现时复开原通知并增加出现次数。
- 支持单条已读、全部已读、处理中/已解除/全部筛选，以及按项目筛选。
- 工作台通知铃和侧边栏展示实时未读数量，并可进入通知中心。
- 通知行动链接可返回具体项目的预算、增减项或付款页签。
- 邮件摘要默认关闭；用户可以主动开启，并选择每天或每周摘要。
- 新增独立邮件摘要执行器，复用阶段 5 的 SMTP 配置，不引入新的 API Key。
- 增减项新增预算类别，报价转为合同基线时记录来源报价，以支持分类预算预测。

## 风险规则

| 编号 | 触发条件 | 级别 | 定位对象 |
|---|---|---|---|
| A1 | 增减项处于待确认或修订中 | 提示 | 增减项 |
| A2 | 已批准预算高于合同基线 | 关注 | 项目预算 |
| A3 | 预测结算达到资金上限 90%，但尚未超限 | 警告 | 项目预算 |
| A4 | 预测结算超过资金上限 | 严重 | 项目预算 |
| A5 | 已知分类预测金额超过分类上限 | 警告 | 预算分类 |
| A6 | 付款节点已到或 7 天内到期，且验收缺失、不通过或仍有问题 | 警告 | 付款节点 |
| A7 | 待确认增减项超过 48 小时未处理 | 提示 | 增减项 |
| A8 | 节点有效实付超过节点计划金额 | 严重 | 付款节点 |

A3 与 A4 互斥。A6 只检查尚未付清的临近或逾期节点。作废和冲正金额沿用预算服务的有效金额口径。

## 分类预算口径

迁移为 `baseline_versions` 增加 `source_quote_id`，当用户从已校对报价建立合同基线时记录来源。分类预测由以下已知金额组成：

```text
来源报价的分类金额
+ 已批准分类增减项
+ 待确认分类增减项
```

手工创建且没有来源报价的旧合同基线无法还原分类组成，因此只计算之后已经分类的增减项，不猜测历史分布，也不会用多份候选报价重复累计。

## 数据结构

迁移 `9ca27d6f8b41_notifications_and_risk_alerts.py` 增加：

- `notifications`：用户、项目、规则编号、级别、对象、行动路径、唯一去重键、已读时间、解除时间、首次/最近触发时间和复开次数。
- `notification_preferences`：邮件开关、每天/每周/关闭频率和最近摘要时间；默认关闭，避免隐式订阅。
- `change_orders.category`：增减项预算类别。
- `baseline_versions.source_quote_id`：合同基线的来源报价。

项目到期删除时，通知会在项目记录删除前一并清理；账号级邮件偏好继续保留。

## 接口

- `GET /api/v1/notifications`：协调当前用户全部项目风险并返回摘要和通知列表。
- `GET /api/v1/notifications/unread-count`：返回未读数和严重风险数。
- `POST /api/v1/notifications/{notification_id}/read`：标记单条已读。
- `POST /api/v1/notifications/actions/read-all`：标记全部或指定项目的活动通知已读。
- `GET /api/v1/notification-preferences`：读取邮件摘要偏好。
- `PATCH /api/v1/notification-preferences`：修改邮件摘要开关与频率。

项目总览请求也会执行当前项目风险协调，因此业务状态变化后的下一次界面刷新会同步创建或关闭对应风险。

## 邮件摘要

执行器入口：

```bash
cd backend
source .venv/bin/activate
python send_notification_digests.py
```

执行器只处理已到频率且仍有活动风险的用户，将风险级别、项目名称、标题和说明汇总为纯文本邮件。投递成功后才更新 `last_digest_at`；失败保留原时间，便于下一轮重试。

生产环境应使用 veFaaS 定时触发器、CronJob 或同等调度设施定期运行该命令。开发模式不会假装投递邮件；必须配置阶段 5 已使用的 SMTP 环境变量。

## 前端与交互

通知中心按用户指定的 `gpt-taste` 规范实现。本阶段确定性种子为 9，采用 Artistic Asymmetry、Outfit 字体、标题内联图片、无限跑马灯和处理原则轮播，并使用滚动固定风险队列及图片缩放淡出。

页面遵循 AIDA：非对称风险 Hero 建立优先级；7+5、4+4+4 的无缝 Bento 展示当前信号；四级风险区和固定队列帮助理解；最后以“先处理风险，再继续付款”行动区收束。风险级别同时显示图标、文字和颜色。移动端主标题保持三行以内，所有点击区域和筛选均可使用键盘操作。

## 当前边界

- 风险协调目前在项目总览和通知接口请求时执行；生产规模扩大后应迁移到业务事件队列和周期兜底任务。
