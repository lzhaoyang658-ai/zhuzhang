# 第 2 阶段技术开发文档｜Beta 报价智能化

> 本阶段是 Beta 的第一条纵向切片，范围集中在 PRD 的 FR-1.2、FR-1.3 与 UAT-01，不代表全部 Beta 功能已经完成。

## 一、阶段目标

- 支持 XLSX、CSV、文本 PDF、扫描 PDF、JPG、JPEG、PNG 和 HEIC 报价入口，单文件不超过 30 MB。
- 解析结果只进入待校对状态；关键字段显示来源位置、原文与置信度。
- 用户可修改项目名、空间、类别、数量、单位、单价与合价相关字段，所有修正写入评估日志。
- 支持任意 2～3 份候选报价生成相似条目建议和确定性金额差异。
- 原文件可回看；报价未人工确认前不能建立合同基线。

## 二、解析架构

```text
上传与真实类型检查
  ├─ CSV/XLSX → 表头别名识别 → 确定性字段映射
  ├─ 文本 PDF → pypdf 文本层 + pdfplumber 表格
  └─ 扫描 PDF/图片 → Poppler 渲染 → Qwen3.6 Flash 结构化视觉解析
                                      ├─ 低置信度 → Qwen3.7 Plus 复核
                                      ├─ 视觉失败 → Qwen3.5 OCR + Plus 二次结构化
                                      └─ 服务异常 → Tesseract chi_sim+eng 本地回退
                                      ↓
标准名称与类别规则 → 金额按整数分重算 → 待校对草稿
                                      ↓
人工修正日志 → 报价确认 → 2～3 报价匹配/基线
```

本地 OCR 是无模型 Key或模型服务异常时的可复现基线。项目名称标准化、施工分类、金额校验和相似匹配继续使用版本化确定性规则；模型只负责从视觉来源抽取候选字段。

## 三、可信输出与回退

- 表格字段置信度为 100；文本 PDF 默认 88～92；OCR 结构置信度最高 72，确保界面突出提示人工核对。
- AI 结果经过 Pydantic 字段校验；平均模型置信度低于 75、字段完整率低于 70% 或报价页无条目时自动升级到 Plus。
- AI 返回的数量、单价和合价由后端再次计算；不一致条目最高 65 分并强制进入人工复核。
- 模型请求设置连接/总超时、429/5xx 指数退避重试；错误信息不记录 Key 或原始报价正文。
- 每条记录保存页码/表格/行号或 OCR 行号、原文摘录和字段置信度。
- 数量和单价可解析时，后端覆盖模型/用户提交的合价并重新计算。
- 扫描 PDF 本地 OCR 最多处理前 20 页并返回警告；持久异步任务已在下一切片完成，更大文件与多实例队列仍属于生产化范围。
- 加密 PDF、损坏文件、扩展名与内容不符、缺少 OCR 组件或无法识别完整报价行时进入明确失败状态，不生成猜测金额。
- 失败文件保留来源与失败原因，不占 3 份有效候选报价名额；用户可改用模板或手工录入。

## 四、数据与 API

新增数据：

- `Quote.input_type/parse_method/parser_version/page_count/warnings/error_message`；
- `QuoteItem.source_excerpt/field_confidences/material_info/craft_notes`；
- `QuoteCorrection`：字段、修改前后值、操作者和时间。

新增或扩展接口：

- `POST /api/v1/projects/{id}/quotes/import`：接收表格、PDF 和图片；
- `GET /api/v1/quotes/{id}`：返回草稿、来源与评估信息；
- `GET /api/v1/quotes/{id}/source`：回看受控原文件；
- `PATCH /api/v1/quote-items/{id}`：保存字段修正并重算金额；
- `GET /api/v1/projects/{id}/quotes/compare?quote_ids=...`：生成 2～3 报价匹配建议；
- `POST /api/v1/quotes/{id}/confirm`：完成人工确认；
- `POST /api/v1/quotes/{id}/activate-baseline`：仅允许已确认报价建立新基线版本。

## 五、样本与实测

样本清单位于 `samples/quote_corpus/`，实际二进制文件位于被 Git 忽略的 `backend/data/sample_quotes/`。

- 三份合成住宅报价各 8 项，基准总额分别为 35,570.00、34,941.48 和 36,818.44 元。
- 合成 JPG 经本地中文 OCR 成功召回 8/8 条，关键合价汇总与基准完全一致；名称仍存在空格与少量错字，因此全部标为低置信度并要求人工校对。
- 同一合成 JPG 经 `qwen3.6-flash-2026-04-16` 真实 API 冒烟召回 8/8 条，总额 3,557,000 分与基准完全一致；输入 2,917 tokens、输出 1,114 tokens。
- 旋转 1.7°、对比度降至 62%、轻度模糊并以 JPEG 质量 48 重压缩后，主模型仍召回 8/8 条且总额完全一致；输入 2,939 tokens、输出 1,114 tokens。
- 27 页低分辨率公开扫描清单无法可靠重建完整报价行，正确进入解析失败回退。该结果说明本地 OCR 还未达到 PRD 的发布质量门槛。
- 官方空白家庭装修报价表用于验证表头、文本层和页码定位，不计入条目召回率。

## 六、自动化与浏览器验收

- 后端覆盖 CSV 解析、文本行解析、名称标准化、修正日志、金额重算和三报价匹配。
- 前端通过 ESLint、TypeScript 与 Next.js 生产构建。
- 浏览器验收覆盖 3 份候选报价、8 个低置信度 OCR 条目、校对保存、11 个对比组、原文件入口、桌面/390px 手机布局、控制台和失败请求。
- 真实浏览器观测结果为零控制台错误、零失败网络请求、移动端无水平溢出。
