# 第 3 阶段技术开发文档｜Beta 异步任务与人工匹配

## 一、完成范围

- 报价上传改为 `202 Accepted`，文件落盘后立即创建持久解析任务。
- 前端每 1.5 秒轮询任务状态，展示排队、解析、保存、成功或失败进度；用户离开页面不影响任务执行。
- 服务启动时把遗留的 `queued/running` 任务重新排队，失败任务最多允许执行 3 次。
- 2～3 份报价的系统匹配建议可人工确认、持久保存和解除，之后重新打开对比仍使用人工关系。
- 任务和匹配操作均进入项目审计时间线。

## 二、任务状态

```text
queued → running → succeeded
             └──→ failed → queued（人工重试）
```

`QuoteParseJob` 保存进度、阶段、执行次数、解析方式、错误信息和起止时间。上传接口只负责校验、落盘和入队；后台执行器使用独立数据库会话完成解析与报价条目事务写入。当前执行器是双线程单机实现，适合本地 Beta，不等同于生产队列。

## 三、人工匹配数据

- `QuoteMatchGroup` 保存项目级标准名称和确认人。
- `QuoteMatchMember` 保存组与各报价条目的关系，并对 `quote_item_id` 设置唯一约束。
- 同一人工组不能包含同一份报价的两个条目；已归组条目必须先解除关系才能重新确认。
- 比价时先装载人工组，再对未人工归组条目运行相似度建议，避免系统结果覆盖人工判断。

## 四、新增接口

- `GET /api/v1/quote-jobs/{job_id}`：读取任务状态与进度。
- `POST /api/v1/quote-jobs/{job_id}/retry`：将未超过次数上限的失败任务重新入队。
- `POST /api/v1/projects/{project_id}/quote-match-groups`：确认 2～3 个跨报价条目的匹配关系。
- `DELETE /api/v1/quote-match-groups/{group_id}`：解除人工匹配。

## 五、界面与交互

报价页使用编辑式分栏和 12 栏任务台。解析任务以可轮换反馈卡展示进度；解析中的报价不可校对或参与比价，失败任务提供原位重试。对比表明确区分“系统建议”和“已人工确认”，所有按钮都有可访问名称，并支持 `prefers-reduced-motion`。

## 六、验证结果

- Alembic 在全新 SQLite 数据库上从初始版本连续升级到 `b89e31c6d2a4`，本地既有数据库已核对表结构并补记版本。
- 后端 `pytest`：14 项通过，覆盖异步成功、失败重排、金额修正、三报价匹配及人工关系持久化/解除。
- 前端 TypeScript、ESLint 和 Next.js 生产构建通过。
- Playwright 真实浏览器验证 3 次上传均返回 202，3 张报价卡完成解析；人工匹配在关闭并重新打开后保留，解除成功。
- 桌面与 390px 移动端零控制台错误、零失败请求，页面宽度 `390/390`，无横向页面溢出。
