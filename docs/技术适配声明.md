# 技术适配声明

## 1. 产品形态判断

- 产品类型与核心任务：面向装修业主的预算、增减项、验收和付款事实链管理工具。
- 核心交互：分阶段确认；外部确认与付款前人工判断是业务成立的必要环节。
- 开发路径：纵向切片。每条切片同时包含最小界面、服务端规则和持久化状态。
- 当前阶段范围：V1.0 Beta 第一条纵向切片；在 Alpha 闭环上增加 PDF/图片识别、字段级校对与三报价对比。

## 2. 采用的默认方案

- Python 3.11 + FastAPI + Pydantic：实现可独立测试的版本化 API。
- SQLite + SQLAlchemy + Alembic：业务实体关系多、包含金额事务和审计要求。
- pytest：覆盖金额计算、状态机、付款前检查和幂等路径。
- Next.js + TypeScript + Tailwind CSS：首发终端为响应式 Web，兼容手机浏览器。
- `/api/v1`：为后续客户端演进保留稳定接口边界。

## 3. 触发的按需模块

- 关系型数据库：由项目、基线、变更、验收、付款、证据和审计关联触发，本阶段引入。
- 文件处理：支持 CSV/XLSX 确定性导入、文本 PDF 表格/文本提取、扫描 PDF 与图片 OCR；文件元数据入库、原件保存在受控目录。
- 后台任务：Alpha 的基础导出同步完成；大文件异步任务留到 Beta。
- AI/OCR：本地使用 Poppler + Tesseract 完成可离线测试的 OCR 基线；结果带来源和置信度并强制人工校对。真实视觉模型尚未接入，不用 OCR 结果冒充模型验收。

## 4. 偏离或暂缓的默认方案

- 正式验证码登录：当前以本地演示账号完成业务闭环；上线前必须接入真实身份认证、会话、速率限制和权限专项测试。
- 家庭协作者、购买权益、邮件通知与生产认证仍按后续 Beta 范围暂缓。
- 对象存储、PostgreSQL、任务队列：本地 Alpha 使用 SQLite 与本地私有文件目录；生产迁移时重新评估。
- 真实模型冒烟：当前已完成本地 OCR 和 mock/确定性自动化；接入真实视觉模型前仍不能判定 AI 发布门槛达标。

## 5. 强制底线检查

- 密钥与隐私：通过；前端不接触密钥，`.env` 被忽略，仅提交 `.env.example`。
- 数据与任务可恢复：通过；重要业务状态写入 SQLite，关键动作追加审计事件。
- 输入输出校验：通过；API 请求/响应使用 Pydantic，金额统一按人民币分计算。
- 错误与日志边界：通过；统一错误结构，不向用户显示堆栈。
- 测试与真实模型验收：离线自动化、构建和浏览器验收已覆盖 OCR 草稿与三报价对比；真实模型调用契约与冒烟待补。

## 6. 需要产品经理决定的问题

开发继续不需要新增付费平台。进入真实视觉模型验收前需要产品经理提供选定厂商的 API Key 和成本上限；没有 Key 不阻塞当前工程开发。
